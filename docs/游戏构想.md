## 0. 一句话

> **你拿到一份不完整的情报、九个人，和一张没有路的地图。**
> **任务不是消灭敌人——是在被发现之前，看见、记住、然后离开。**

## 1. 已确认的方向（2026-10-25，负责人决定；后续设计不得违背）

| # | 决定 | 含义 |
|---|---|---|
| 1 | **2D，文字为主** | 不追求画面表现力；画面服从文字。文字承担设定、叙事、情报与决策。 |
| 2 | **章节制** | 游戏分为许多章节，每一章 = 一次需要决策的任务（+ 一次队伍关系的推进）。 |
| 3 | **核心是"指挥"，不是"作战"** | 玩家下命令、做判断、承担后果；不操作枪械，不打实时战斗。 |
| 4 | **任务以潜伏、侦察、与其他队伍配合为主** | 自家小队不以交火为主；交火＝失败后的补救（与"猞猁准则"一致）。 |
| 5 | **主要游玩点＝博弈** | 与看不见的对手博弈、与环境博弈、与自己的人博弈。 |
| 6 | **成员靠"相处"被了解** | 先用简洁文字介绍九人（快速上手），再在相处中逐渐了解他们。 |
| 7 | **项目名 ILVES／《猞猁小队》** | Unity 工程 D:\UnityProjects\ILVES，GitHub 仓库 ILVES。 |
| 8 | **全篇 5–7 章，单章 15–30 分钟** | 不追求长线，追求每章一次完整的“决策 → 代价 → 复盘”。 |
| 9 | **强连续** | 上一章的伤员、暴露、信任与关键选择必须带进下一章；故事线连续，不重启。 |
| 10 | **保留俄语术语／呼号，但必须解释** | 呼号、军语、番号保留原文（如 «Хозяин»），**首次出现时在括号里给中文解释**。 |

> 被否掉的方向（记为"不做"，避免以后反复）：3D 场景、第一人称、实时射击、塔防式布阵、抽卡养成、纯视觉小说（无决策）。

## 2. 体验目标

玩家离开游戏时应该能复述的，不是"我打死了多少"，而是：

- "我为了绕开那片沼泽，晚了四十分钟，目标走了。"
- "我知道谢苗在怀疑，但我不敢关电台。"
- "我带回来了八个人。第九个是我决定不救的。"

**情绪曲线**：压抑的平静 → 一次意外 → 被迫的取舍 → 撤离时的沉默 → 复盘时的重量。

## 3. 核心循环（一章之内）

```
任务简报（不完整、带矛盾）
   ↓
情报研判  ← 地图、档案、截获通信、上级口径
   ↓
[可选] 前出侦察（提高置信度，但增加暴露）
   ↓
制定方案：路线 / 分工 / 交战规则(ROE) / 撤离点 / 应急预案
   ↓
执行：逐节点推进，每个节点一个决策（约 15–25 个）
   ↑         ↓
   └── 意外：环境恶化 / 队员裂缝 / 敌方反制
   ↓
撤离或收尾（可能失败但活着回来）
   ↓
复盘：暴露度、耗时、伤员、情报质量、是否达成目标
   ↓
章节之间：关系变化、装备损耗、上级信任、敌方记住你的打法
```

**为什么是"节点"而不是"回合制战斗"**：节点＝一个需要判断的处境（岔路、哨位、可疑脚印、无线电阻断、雪盲、伤员），玩家选择"怎么做/谁去做/做不做"。决策密度高，战斗密度低。

## 4. 博弈系统（本作的核心卖点）

### 4.1 第一重：与"对手指挥官"博弈

- 敌方不是脚本触发器，而是一个**有性格模板的决策者**（谨慎／激进／程序化／老练）。
- 它有自己的信息与误判：它看到的是你的**痕迹**，不是你。
- 你的每个动作都会留下信号：噪音、脚印、被剪断的铁丝、尸体、无线电呼号、被发现的侦察。
- 对手读信号 → 改变巡逻、设伏、请求增援、提前转移目标。
- **你可以主动"喂信号"**：佯动、假电台、故意留下的痕迹。这是本作最重要、最好玩的一个动词。

### 4.2 第二重：与环境博弈

冷、湿、虫、距离（设定原文的"第一敌人"）不是数值装饰，而是决策约束：

- 沼泽吃掉时间与体力，雪原暴露身影与热量，树冠切断链路；
- 时间越久，体温、电力、对手反应都在恶化；
- **"再往前走一步"永远是有代价的**。

### 4.3 第三重：与自己的人博弈

- 九个人各有裂缝（见设定集）。他们会**按自己的性格执行命令**，而不是完美执行。
- 你越了解一个人，他的行为越可预测；不了解，他就会在关键时刻给你一个"意外"。
- 命令不是"点击生效"：模糊的命令会被各自理解，明确的命令会激起各自的抵触。

### 4.4 信息不对称的规则化

| 概念 | 说明 |
|---|---|
| 情报置信度 | 每条情报带"来源／时间／可信度"，玩家看到的是**概率**不是事实 |
| 未知区 | 地图上有大块留白，不侦察就永远是黑的（不是战争迷雾，是"没有情报"） |
| 对手模型 | 玩家可以在笔记本上推演对手性格（游戏内提供"研判"界面） |
| 暴露度 | 一个可被玩家看见、但不可精确计算的累积值；它不是血条 |

## 5. 九个人：从"简历"到"熟人"

### 5.1 三层信息释放

1. **入队简报（序章）**：简洁文字介绍九人——姓名、代号、岗位、一句话性格（就是设定集"九人总表"）。**目的：三分钟内知道谁是谁。**
2. **任务中**：通过命令反馈、无线电短句、意外反应认识他们（"原来他会这样"）。
3. **相处中**（营地、行军、撤离途中）：短对话，玩家选择回应方式，逐渐知道他们为什么是这样。

### 5.2 关系不是好感度

关系值衡量的是**可预测性**与**信任**，不是"喜欢"：

- 信任高：他会执行你的冒险命令，并在你不说的时候替你补位。
- 信任低：他会按自己的判断行事，甚至当众质疑你（基里尔会，伊戈尔也会）。
- 了解深：解锁隐藏信息（谢苗为什么怀疑一切）、专属指令（罗曼的"再等一等"）、以及某些章节的**额外解法**。

### 5.3 每个人 = 一套动词 + 一个裂缝 + 一条线

| 队员 | 动词 | 裂缝（会在任务中触发） |
|---|---|---|
| 瓦西里（你） | 决策、授权、放弃 | 保守：你会不自觉地绕路 |
| 伊戈尔 | 前出、引导、侦察 | 好胜：他会把"可以打"说成"应该打" |
| 罗曼 | 潜伏、狙杀、评估 | 孤立：他会消失在自己的世界里 |
| 阿尔乔姆 | 观察、救治、稳定 | 见伤就上：他会为救人暴露全队 |
| 谢苗 | 静默、开台、干扰 | 多疑：他会把友军当敌人 |
| 基里尔 | 破门、突入、抓捕 | 冲动：他会先动手再报告 |
| 德米特里 | 布雷、排雷、爆破 | 谨慎：他会因为一颗老雷耽误一小时 |
| 尼古拉 | 驾驶、运输、探路 | 依赖载具：他会拒绝徒步方案 |
| 帕维尔 | 压制、掩护 | 护枪：他会在关键时刻先修枪 |

## 6. 文本与画面（文字在前，画面在后）

### 6.1 三种文本载体

| 载体 | 语气 | 用途 |
|---|---|---|
| **任务档案** | 公文、冷、带编号与密级 | 简报、地图描述、情报条目、上级口径 |
| **无线电** | 短、断、有噪音（用排版与符号表现） | 实时反馈、队员报告、敌方通信截获 |
| **队员对话** | 口语、有性格、有停顿 | 相处、质疑、玩笑、崩溃 |

### 6.2 画面策略

- **单色（橄榄绿 + 近黑）+ 线条**，沿用队徽语言；不做彩色渲染。
- 2D 态势板：等高线、林线、沼泽纹理、道路、哨位、撤离点——**像一张手绘作战图**，而不是游戏地图。
- 人物：签字式肖像／剪影／臂章，一人一形；**不做立绘动画**。
- 动效只在"信息到达"时使用（打字机式文本、无线电闪烁、地图上新增标记）。
- 音频：林声、风、雨、无线电流、远处的狗吠；枪声极少——因为很少开枪。

**修订（2026-10-30）**：负责人提供了主界面 key art——一张泰加林黄昏的彩色场景图、一个单色标题字标、一张满幅单色应用图标，主界面／标题页已改用这套图（背景叠暗化遮罩后压文字）。**正文、简报、复盘等游玩界面仍严格维持单色线条风格**，上面几条策略对它们照旧有效；这次只是画面表层的一次例外，不是风格转向，所以「文字优先、画面服从文字」的结论不变。

〔待负责人确认〕这是负责人本次提供素材后的落地做法；若后续判断它构成方向变更（而非仅主界面例外），再回写进第 1 节与设定集 §3.5。

### 6.3 为什么"文字优先"是对的

1. 本作卖的是**判断**，判断需要信息密度，文字的信息密度最高。
2. 2D 文字让"九个人 + 一张地图 + 大量分支"可控，一个人也能做完。
3. 与题材同构：一支侦察小队的世界本来就是**报告、地图、无线电、笔记**。

## 7. 章节结构（已确认 6 章，详见 docs/游戏大纲.md）

| 章 | 名称（暂） | 教学/主题 | 新机制 |
|---|---|---|---|
| 序章 | 入队 | 认识九个人；第一课：**不开枪也能完成任务** | 指令、地图、情报板 |
| 第一章 | 边境线上的眼睛 | 潜伏与侦察；目标是"看见"，不是"打掉" | 情报置信度、暴露度 |
| 第二章 | 另一支队伍 | 与其他队伍配合；信息不同步、指挥权暧昧 | 友军 AI、协同指令 |
| 第三章 | 雨与沼泽 | 环境成为主要对手 | 体力/时间压力、载具取舍 |
| 第四章 | 静默 | 通信被渗透；信任危机 | 电子战、无线电静默的代价 |
| 第五章 | 佯动 | 主动"喂信号"欺骗对手 | 欺骗系统、对手模型升级 |
| 终章 | 九个人进去 | 主题回收：任务 vs 带人回去 | 多结局结算 |

> 每章目标结构：1 个主任务 + 2–4 个关键决策 + 1 个关系场景 + 1 次复盘。

## 8. 失败、评价与存档

- **不做"读档惩罚"**：任务可以失败但活着回来（暴露、目标丢失、任务中止），剧情继续。
- 评价维度（对应猞猁准则）：是否达成目标 / 暴露程度 / 耗时 / 伤员 / 情报质量 / 是否遵守 ROE。
- **战役层**：队伍存续、伤员恢复、装备损耗、上级信任、敌方对你的"印象"。
- 多结局轴：**你带回了几个** × **你被多少人记住**。

## 9. 技术方案（Unity 6.3 LTS）

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Unity 6000.3.27f1（已装） | 唯一安装版本，许可有效 |
| 形态 | 2D + UI 为主，无 3D、无物理、无实时战斗 | 与"文字优先"一致 |
| UI | **uGUI + TextMeshPro**（MVP）；文本排版复杂后再评估 UI Toolkit | TMP 中文与富文本成熟，2D 场景/精灵方便 |
| 架构 | **纯 C# 逻辑层（无 Unity 依赖）+ Unity 表现层** | 可单测、可移植（以后可做网页版） |
| 数据 | ScriptableObject 存章节/节点/队员/情报；剧情文本外置（JSON/YAML + 本地化键） | 策划可改，不用动代码 |
| 存档 | JSON，按章节快照 | 可读、可调试 |
| 平台 | Windows 优先（本机只有 Windows 模块） | 后续再补 WebGL/Android |
| 语言 | 中文为主，英文为副（同一套键值） | 中英双语 |

## 10. MVP：第一个可玩切片

**范围（只做这些）**

1. 序章 + 第一章，共 1 个完整任务；
2. 15–20 个决策节点；
3. 情报板 + 2D 地图 + 指令栏 + 队员状态；
4. 3 个可失败状态（暴露过高、时间耗尽、有人重伤）；
5. 复盘界面 1 页；
6. 2 个"相处"对话场景。

**验收标准**：一个没读过设定的人，能在 10 分钟内完成第一章，并说出"我为什么那样决定"。

## 11. 风险与待定

| 风险 | 应对 |
|---|---|
| 文本量大，写作是主要瓶颈 | 先定"节点卡"模板，一章一章写；AI 辅助初稿，人工定稿 |
| 博弈系统容易被算出最优解 | 信息噪声 + 对手随机化 + 不可逆代价 |
| 指挥游戏容易退化成"点按钮" | 每个决策必须有代价；关键决策不超过 4 个/章 |
| 2D 文字卖相弱 | 用地图与排版做视觉记忆点；单色风格统一 |

**待负责人确认（下一轮）**

1. 单章时长目标（30 分钟？60 分钟？）
2. 是否要"上一章的选择影响下一章"的强连续性（还是每章独立）
3. 是否需要中文配音（建议不要，成本高）
4. 是否做"同行评审/复盘"式的元界面（像作战汇报）
