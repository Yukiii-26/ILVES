# 命名提案｜ООСпН «Илвес» · 猞猁小队

> 用途：Unity 项目名 / GitHub 仓库名 / 商店页标题 / 世界观品牌
> 范围：为「卡累利阿泰加林 · 九人远程侦察袭扰小队 · 玩家扮演队长做决策与调度」这款战术游戏提供命名方案
> 日期：2026-10-25 ｜ 版本：v1（供 lead 与后续文档/UI 任务引用）
> 结论先行：**主推 `ILVES` / `猞猁`**；若商店页更需要"一眼看出是战术游戏"，用 `DEAD GROUND` / `死角`。

## 0. 一页结论

| 场景 | 推荐 | 理由一句话 |
|---|---|---|
| 最终游戏名（首选） | **ILVES / 猞猁** | 部队自己的名字，动物行为＝指挥哲学，与现有徽章零成本对接 |
| 若要多平台商店页更好卖 | **DEAD GROUND / 死角** | 军事地形术语：看不见也打不到的地面，正好是本作的核心决策 |
| 若要把"九个人"写进标题 | **NINE PINES / 九松** | 九个人、九棵树；撤离点数人头的那一刻，名字自己会说话 |

## 1. 命名策略：中英文是否同源

### 1.1 三种模型

| 模型 | 做法 | 例子 | 优点 | 代价 |
|---|---|---|---|---|
| **A 同源直译** | 中英是同一个词的互译 | `Dead Ground` / `死角` | 记忆统一、物料可复用、翻译不打架、社区只有一个叫法 | 同一词在两种语言里"分量"不同，必有一边偏平；直译容易生出翻译腔中文名 |
| **B 意象同源 · 词形独立** | 同一种画面，各自用本语言最自然的词 | `Kelo` / `寒枝` | 两边都像母语命名，中文可以真正"克制" | 需要一句解释来绑定；双语物料要各写一套 |
| **C 各自独立** | 两套名字互不相关 | — | 各自最优 | 品牌资产分裂、社区称呼混乱、搜索要买两份 |

**结论：以 B 为骨架、A 为上限，不采用 C。**

### 1.2 四条落地规则

1. **英文是"法律名 / 工程名 / 搜索名"，中文是"发行名 / 口碑名"。**
   英文必须是 ASCII 单词，能当 C# 命名空间、能当 repo slug、能当 exe 名；中文只承担语感与留白。
2. **中文可以比英文更文学，但不能和英文打架。**
   不能英文叫 `Dead Ground`、中文叫「雪原猎手」——两套意象必须指向同一幅画。
3. **允许"意象同源、词形独立"，但必须能用一句话解释。**
   例如 `Kelo` / 「寒枝」：英文是泰加林里枯死却不倒的松树，中文取自苏轼「拣尽寒枝不肯栖」——"冷木头"与"不肯栖/不肯倒"对位。解释不清的配对，一律视为 C 类，放弃。
4. **不做音译。**
   「伊尔维斯」「科尔皮」这类音译在中文里没有记忆点，也不产生画面；中文名必须自己成立。

### 1.3 一个必须先说清的硬约束

Unity 的 **Product Name / Company Name 会被刻进存档路径与注册表**：

- build 产物名（`Ilves.exe`）与 Steam 启动项指向的可执行文件名；
- `Application.persistentDataPath` = `...\AppData\LocalLow\<Company>\<Product>`；
- Windows 下 PlayerPrefs 存在 `HKCU\Software\<Company>\<Product>`；
- 移动端 Bundle ID / Application ID 发布后**永久不可改**。

所以：**工程名必须最先冻结，且只能是 ASCII**；市场名（中文名、商店页标题、宣传语）可以之后再改。中文名不进 Unity Product Name（可放 Steam 本地化名）。

### 1.4 本项目的一个特殊资产

小队名 `ООСпН «Илвес»` 与队徽已经存在（西里尔文 + 橄榄绿单色线）。建议：

- 队徽上的西里尔文保持 **diegetic**（世界观内的部队标记，出现在臂章、档案、任务简报里）；
- 游戏标题锁定版使用 **拉丁字母 `ILVES`**；
- 两者可以并存，就像真实部队的臂章与出版物的书名不是同一套字体。

## 2. 候选池（21 个，三个方向）

### 2.0 评估口径

每个候选给六项：**English 名 / 中文名 / 一句话意象 / 语感与发音 / 玩法契合 / 撞名与搜索风险 + repo slug**。
风险说明里，凡写「已核实」的，是我在本轮实际抽查到的具体占用（Steam / IndieDB / GitHub / 网页）；凡写「未查到」的，只代表本轮抽查未命中，不等于商标安全（见 §6.2 免责）。

### 2.A 军事代号风（7）—— 构词像真实番号、呼号或军中口令

#### A1　ILVES / 猞猁
- **意象**：部队自己的名字——卡累利阿语里那只"盯着你们看很久，咬一口就走"的动物。
- **语感**：`IL-ves`，五字母两音节，齿音收尾。英语读者会读成近 "IL-vess"，芬兰语/俄语读者读 "EEL-ves"，都不拗口；天然带"非英语部队"的陌生感。
- **玩法契合**：动物行为＝指挥哲学。玩家下达的每一条命令，都是"猞猁准则"的一次执行；名字与玩法同构，不需要额外解释。
- **风险**：芬兰坦佩雷冰球队 Tampereen Ilves、爱沙尼亚 FC Ilves（体育领域，类别不同，但搜索结果会混）；未查到同名战术游戏；"Lynx"本身重度占用（雅达利掌机、Squad 里的 ATV、机载计算机），`Ilves` 反而干净。中文「猞猁」是标准动物名，无商标冲突；但中文语境里它偏"科普/纪录"，要靠封面与副标题把它拉回"游戏"。
- **slug**：`ilves`
- **结论**：最诚实、最省事的一个，与现有徽章零成本对接。

#### A2　KORPI / 深林
- **意象**：芬兰语/卡累利阿语里"偏远的老林子"——走进去，地图就失效的那种。
- **语感**：`KOR-pi`，硬辅音夹圆元音，像一句压低的无线电呼号；英语里会被读成 "CORP-ee"，离 corpse 只差一个音——对一支要人命的队伍，这不算坏事。
- **玩法契合**：小队的主场就是 korpi；玩家反复做的决定是"要不要再往林子里走一步"。
- **风险**：⚠️ **已核实**：存在一家独立游戏工作室 **Korpi Games**（近期还在发布新作公告）——作游戏名会与另一家公司混淆，这是实质撞名；芬兰语里还是常见姓氏。段位：中高。
- **slug**：`korpi`
- **结论**：意象满分、撞名扣分。**建议降级为内部工程代号或系统名**（例如地形系统叫 `Korpi`），不作发行名。

#### A3　KELO / 寒枝
- **意象**：泰加林里枯死却站着不倒的松树，树皮被风雪磨成银灰——林子里唯一不会移动的地标。
- **语感**：`KE-lo`，四字母两个开音节，念起来像一句被截断的口令；短到可以直接做成一个竖线的 logo。
- **玩法契合**：指挥官的导航靠地标；kelo 是那种"地图上不一定有、但老兵记得"的点。玩家在雨雾里认出它，就知道自己走到哪了——这是"读地形"的具体化。
- **风险**：芬兰 1990 年代有电影《Kelo》；美国有广播台呼号 KELO；未查到同名游戏。英文里无词义，需要一句解释（商店页第一行就能解决）。中文「寒枝」与英文**非同源**，靠"冷木头 + 不肯倒/不肯栖"对位，属于 §1.2 规则 3 的 B 类。
- **slug**：`kelo`
- **结论**：气质最好，商业化最弱。

#### A4　STAND-TO / 待战
- **意象**：stand-to 是军队在黎明/黄昏的全员上阵地——最可能被摸哨的时刻，也是"顶住"。
- **语感**：`STAND-toe`，两个最硬的英语音节；连字符让它看起来像一份作战文件。
- **玩法契合**：本作大量时间是"等"——等目标出现、等窗口、等撤离；stand-to 是"等"的军事化形态。但本作的主动方向是渗透而非防守，方向偏了半格。
- **风险**：未查到同名游戏；但 "stand to" 是通用短语，搜索会被稀释；连字符对口播与仓库名都要额外处理。
- **slug**：`stand-to`
- **结论**：军事质感最正，但语义指向与本作相反。

#### A5　DEADFALL / 倒木
- **意象**：泰加林里成片倒下的枯木，走一步要翻三根；也指猎人用落木做的陷阱。
- **语感**：`DEAD-fall`，两个重音一路下坠，硬、直、有攻击性，英文母语者一眼懂。
- **玩法契合**：倒木是本作的地形阻力（移动、隐蔽、绊线），也是"埋伏"的物证。
- **风险**：2012 年电影《Deadfall》；Steam 上有若干同名小品；"dead + 名词"在游戏里是重度构词模式，会被当成动作片。
- **slug**：`deadfall`
- **结论**：太"打"，与本作"克制"的气质相反。

#### A6　EMCON / 电磁静默
- **意象**：Emissions Control——无线电与雷达的"闭嘴"命令，谢苗那套本领的总称。
- **语感**：`EM-con`，四字母，像设备面板上的一个开关；对军迷极亲切，对普通玩家像密码。
- **玩法契合**：本作的"克制"有一半是电磁纪律——不开电台、不用主动探测、不留信号。这是机制级别的名字。
- **风险**：未查到同名游戏；纯术语，非军迷玩家零联想；中文「电磁静默」是标准军语，四字偏技术文档。
- **slug**：`emcon`
- **结论**：最好的"机制名"，不是最好的"作品名"——适合做系统名（通信/电子战模块）。

#### A7　NINE ACTUAL / 九号长（工作译名，不建议）
- **意象**：无线电里 "Actual" 指指挥官本人；Nine Actual＝"九人小队的本人"——玩家在电台里的身份。
- **语感**：`NINE ACK-choo-al`，重-轻-轻，像在报呼号；两个词都有军事味，却没有 "Operation X" 的俗套。
- **玩法契合**：本作的核心动词是"下令"，而所有命令都经过一部电台；"Actual" 精确说出了玩家的位置。
- **风险**：未查到商业游戏；milsim 社区可能有自建单位，但非商标级；"Actual" 是通用军语，不构成障碍。**中文没有等价词**——中文军语里指挥员是"一号"，硬译"九号长"不通，且「九号」已被九号公司（Ninebot）占用。
- **slug**：`nine-actual`
- **结论**：英文侧最强，中文侧必须另起；可作"英文发行名 + 中文另取名"的双轨案例，不作首选。

### 2.B 自然-动物风（7）—— 猞猁 / 泰加林 / 雪原 / 寒带意象

#### B1　TREELINE / 林线
- **意象**：森林与开阔地的交界线——伏击发生在这一侧，暴露也发生在这一侧。
- **语感**：`TREE-line`，两个实词，念完就知道画面；8 字母，商店页友好。
- **玩法契合**：小队的一生都在林线上：在里面观察，在边缘出手，再退回去。
- **风险**：⚠️ **已核实**：Steam 已有一款 **TreeLine**（app 5064360）。按"不要与 Steam 已有作品高度重复"的硬约束，**直接出局**；另有 timberline 等近似词。
- **slug**：`treeline`（可留作关卡/系统名）
- **结论**：概念最好、名字最不能用。

#### B2　MIRE / 泥沼
- **意象**：沼泽；也是"陷进去出不来"的状态。
- **语感**：`MIRE`，单音节，尾音收得干净；英文里自带"困境"的引申义。
- **玩法契合**：设定的第一敌人是"冷、湿、虫、距离"，湿就是沼泽；指挥官每天都在算"这条路会不会吞掉两小时"。
- **风险**：⚠️ **已核实**：Steam 已有 **Mire**（app 1899210）；"mire" 在英式英语里还有别的联想；中文「泥沼」直白，标题感弱。
- **slug**：`mire`
- **结论**：意象与玩法都对，但已被占。

#### B3　SNAG / 枯立木
- **意象**：枯立木的英文林学术语就是 snag；同时 snag＝计划里突然卡住的那个点。
- **语感**：`SNAG`，单音节，短促、粗粝，像树枝折断。
- **玩法契合**：指挥官的工作就是预判 snag：桥断了、雷区、电台不通——每个 snag 都是一次取舍。
- **风险**：Steam 上有 Snag 相关小游戏（"Snag 'Em All" 等，非同一名）；"snag" 口语里还有"抢到/搞到"的意思；中文「枯立木」是术语，三字偏硬。
- **slug**：`snag`
- **结论**：双关最巧，但英文读者第一反应不一定是森林。

#### B4　ESKER / 石脊
- **意象**：冰川留下的蛇形垄脊，是泰加林沼泽里唯一干燥、唯一能走的路。
- **语感**：`ES-ker`，两个音节都短，像脚步；拼写与发音有轻微不一致（有人会读成 "ee-sker"）。
- **玩法契合**：指挥官的路线选择就是"沿着 esker 走"还是"赌一条近路"——本作最核心的决策之一。
- **风险**：Steam 有 **Echo's Esker**（不同名，但同词根，搜索会被分走）；Esker 还是一家法国 SaaS 上市公司（软件类，与游戏不同类，但域名与搜索会混）；未查到同名战术游戏。
- **slug**：`esker`
- **结论**：地形即玩法，最好的"路线"名字。

#### B5　HALLA / 霜夜
- **意象**：芬兰语"霜"；`hallayö`＝下霜的夜，一夜之间把地面冻硬、把脚印留住。
- **语感**：`HAL-la`，两个开口音，念出来像叹气；英文读者会联想到 hollow，冷而空。
- **玩法契合**：霜是"留下痕迹"的天气——追踪与反追踪都发生在霜上。
- **风险**：韩国 Halla 集团/汉拿山（跨类但搜索混流）；"Halla" 拼写过于常见，SEO 差；霜/寒类词在军事游戏里已经饱和（Frostline、Whiteout 一系）。
- **slug**：`halla`
- **结论**：好听，方向撞车。

#### B6　LARCH / 落叶松
- **意象**：泰加林里唯一会落叶的针叶树，秋天整片金黄，冬天只剩骨架。
- **语感**：`LARCH`，单音节，齿音收尾，硬而干净；比 pine / spruce / fir 都少见。
- **玩法契合**：落叶松是"季节"的指针——玩家靠它判断还剩多少时间、雪什么时候来。
- **风险**：未查到同名游戏；但 "larch" 在英语里偏植物学，普通玩家不认识；中文「落叶松」三字是树名，作标题像科普。
- **slug**：`larch`
- **结论**：好的"地名/关卡名"，不是好的作品名。

#### B7　BIRCH / 白桦
- **意象**：白桦——俄罗斯北方最标志性的树，也是绿林里唯一的亮色。
- **语感**：`BIRCH`，单音节，软腭收尾，温和；容易被人名化（Birch 是常见姓氏）。
- **玩法契合**：白桦是"有人来过"的证据（树皮刻痕、采脂、旧营地）；侦察兵读树如读档案。
- **风险**：白桦水/白桦茸等日用品品牌多，搜索混流；未查到同名游戏；中文「白桦」在中国读者心里连着苏联歌曲与知青文学，情绪偏怀旧，与"特种作战"有温差。
- **slug**：`birch`
- **结论**：气质对，指向偏抒情。

### 2.C 意境-文学风（7）—— 克制、留白、有画面感

#### C1　DEAD GROUND / 死角
- **意象**：军事地形术语——既看不到、也打不到的那块地面；也暗含"埋人的地面"。
- **语感**：`DEAD ground`，两个重音，念完有一种"压低身体"的感觉；11 字符，短。
- **玩法契合**：本作的核心问题是"我站在这里，谁看得见我"。dead ground 是答案、是命令、也是失败的原因；指挥官读地形，读的就是死角。
- **风险**：同名小说至少两部（Graham Hurley；M.W. Craven），书评会占位；"Dead + 名词"在游戏里重度使用（Dead Space / Dead Cells / Dead Rising），可能被误认成僵尸题材；未查到同名商业游戏，但仍需正式检索。
- **slug**：`dead-ground`
- **结论**：机制契合度第一。

#### C2　BATED BREATH / 屏息
- **意象**：屏住呼吸、等目标进入射界的那几秒。
- **语感**：`BA-ted breath`，两个词都带气声，念出来本身就像屏息；但 "bated" 常被误写成 "baited"，这是真实风险。
- **玩法契合**：本作的紧张来自"等"而不是"打"；屏息是玩家每次扣扳机前的状态。
- **风险**：Path of Exile 有同名物品、DriveThruRPG 有同名模组，均非同类；未查到同名游戏；成语感强、商标性弱（这是好事）。
- **slug**：`bated-breath`
- **结论**：中文「屏息」是全表最好的中文名，英文略绕。

#### C3　LIE LOW / 低伏
- **意象**：趴下、不动、等对方走过去；也指低调潜伏。
- **语感**：`LIE low`，两个词都是长元音，念完自然放低声音；口语感强，少了点军味。
- **玩法契合**："不追不恋"就是 lie low 的纪律；但作为标题，它听起来更像谍战片，撑不住"指挥"。
- **风险**：Kumbaracı50 有同名舞台剧；"lie low" 是常用短语，SEO 差；未查到同名游戏。
- **slug**：`lie-low`
- **结论**：气质对，动词标题太轻。

#### C4　NINE PINES / 九松
- **意象**：九个人、九棵树；松枝与松果在徽章上，「九松」就是这支队伍在林子里留下的样子。
- **语感**：`NINE pines`，两个实词，念完有画面；中文「九松」两字，像地名（"九棵松"是东北常见的林场/村屯名），也像一块无字碑。
- **玩法契合**：本作最动人的瞬间是撤离点"数人头"——九个人进去，九个人出来；九棵松就是那个可以数的东西。名字把"编制"写进了标题，而"带几个人回去"是本作真正的胜负。
- **风险**：未查到同名游戏；"Nine" 作为词根在游戏里很密（Nine Sols、Nine、The Nine），SEO 会被稀释；"Nine Pines" 可能撞高尔夫球场/住宅区名（需正式查）；英文读起来偏田园，需靠封面与副标题校正。
- **slug**：`nine-pines`
- **结论**：最"人"的一个名字。

#### C5　NO SUCH UNIT / 不存在的番号
- **意象**：不存在的部队——档案里没有、战报里不写、问起来"没有这个单位"。
- **语感**：`NO such U-nit`，三个词都是短音，念起来像一句搪塞；中文「不存在的番号」六字，冷、纪实、有档案感。
- **玩法契合**：本作的每次越境都是"可否认"的；玩家做的每个决定，上级都可以说"没有这回事"。
- **风险**：未查到同名游戏；但 "No Such Unit" 是常见军事说法，搜索稀释；三词标题在手机图标下要排两行，不理想。
- **slug**：`no-such-unit`
- **结论**：世界观最强，标题最啰嗦。

#### C6　UNMAPPED / 图外
- **意象**：地图上没有画出来的地方；也指"没被记录的行动"。
- **语感**：`un-MAPPED`，重音在后，念完有一种"越界"感；中文「图外」两字，短、冷、留白。
- **玩法契合**：设定里说任务区是"地图上大片留白"；指挥官的每次选择，都是把行动写进留白，或让它永远留在图外。
- **风险**："Unmapped" 是常见词（播客、公司、工具都用），SEO 差；未查到同名游戏；「图外」不是现成词，需要一次解释。
- **slug**：`unmapped`
- **结论**：概念干净，撞词多。

#### C7　NO TRACE / 无痕
- **意象**：走过去不留痕——雪面、泥地、电台、纸面都不留。
- **语感**：`NO trace`，两个词，念完就没了；中文「无痕」两字，现代、冷、好记。
- **玩法契合**：本作的胜利条件不是"消灭"，而是"没人知道你来过"；无痕既是战术纪律，也是撤离标准。
- **风险**：⚠️ **已核实**：已有一款叫 **NO TRACE** 的独立游戏（IndieDB 有页面，PC Gamer 报道过 "Hitman meets Hotline Miami"）——直接出局；中文「无痕」还带"无痕浏览"的日用联想。
- **slug**：`no-trace`
- **结论**：概念最好，名字已有主。

## 3. Top 5（按推荐顺序）

> 排序标准不是"好听"，而是：**它能不能替玩家说出他正在做的那个决定**。

### #1　ILVES / 猞猁

**为什么适合"指挥九人小队"：**

1. **名字与指挥哲学同构。** 设定里的"猞猁准则"——潜伏优先、一击脱离、不追不恋——本质上是一套**指挥纪律**：什么时候进、什么时候不打、什么时候撤。玩家不是在扮演一只猞猁，而是在执行一只猞猁的作战原则；标题就是这份原则的名字。
2. **它是"这支部队"，不是"这场战斗"。** 本作的核心不是某一关，而是九个人组成的系统：侦察—标记—打击—狙击—通信—突击—阻滞。一个动物名能同时容纳九个岗位，而"Dead Ground"之类的词只描述战场，不描述组织。
3. **它已经在你的资产里。** 徽章上写着 `ИЛВЕС`，臂章、档案、任务简报可以直接沿用；命名不需要新建世界观，只需要把已有的东西放大。

**风险与对冲：** 英文玩家不知道 Ilves 是什么动物——商店页第一行给一句 "Ilves: the Karelian word for lynx"，封面用猞猁侧脸，问题就解决了。中文「猞猁」偏科普感——发行时可用副标题或宣传语承接（建议："九个人进去，九个人出来"）。

**一句话宣传语：** `Look. Note. Leave.`（看一眼，记下来，离开）

**工程值：** 5 字符、纯 ASCII、可作命名空间 `Ilves`、可作 repo `ilves`、可作 exe `Ilves.exe`。全表最优。

---

### #2　DEAD GROUND / 死角

**为什么适合"指挥九人小队"：**

1. **它就是这个游戏的决策函数。** 玩家每做一个决定，底层都在问："我站在这里，谁看得见我？"死角的边界＝可行动空间＝指挥的全部。标题直接把机制说破，却不显得说明书。
2. **它同时是"藏身处"和"失误"。** 躲进死角是对的；走进死角是错的。一个词同时命名了本作的成功与失败，这比任何"Operation X"都更像一个系统名。
3. **它替"克制"找到了军事语言。** 不追不恋不是怯懦，是"离开死角之前不再开枪"的专业判断。对军迷它是术语，对普通玩家它是画面。

**风险与对冲：** 同名小说（Graham Hurley、M.W. Craven）会占搜索结果——但书与游戏是不同品类，且可在商店页用副标题区隔；"Dead + X" 可能被误读成僵尸题材——封面必须是林线、雨雾、背影，不能出现怪物剪影。

**工程值：** 2 词 11 字符，命名空间 `DeadGround`，repo `dead-ground`。

---

### #3　NINE PINES / 九松

**为什么适合"指挥九人小队"：**

1. **它把"编制"写进了标题。** 九个人是这支小队唯一的 KPI：任务成功但少一个人，玩家会记得；任务失败但九个都回来了，玩家也会记得。标题提前把这件事摆在桌上。
2. **它给了 logo 一个可数的结构。** 九棵松＝九个名字，可以做成极简的竖排标记，也可以做成撤离点时"数人头"的 UI 母题；徽章上的松枝与松果天然衔接。
3. **它在两种语言里都不需要解释。** 「九松」是地名式的，不喊口号；"Nine Pines" 是画面式的，不装深沉。中文比英文更克制——这正是我们想要的"各自成立"。

**风险与对冲：** "Nine" 在游戏名里很密，SEO 会被稀释——用 `ninepines` / `nine-pines` 双写法与副标题补足；英文偏田园——靠封面（橄榄绿、单色线、林线剪影）把它拉回军事。

**工程值：** 10 字符、两词、命名空间 `NinePines`，repo `nine-pines`（GitHub 上该顶格账号名未被占用）。

---

### #4　KELO / 寒枝

**为什么适合"指挥九人小队"：**

1. **它是"读地形"的最小单位。** 指挥官在图上找不到参照物时，会记一棵不会动的树；kelo 就是那种树。玩家在雨雾里认出它的那一刻，地图从抽象变成了身体记忆。
2. **它把"死"与"不倒"放在同一个词里。** 枯死、站立、银灰——这是这支队伍的自我认知：任务会耗尽你，但你还得站着回去。它比"死亡"克制，也比"生存"冷。
3. **它是全表最不像游戏名的名字。** 这恰恰是它的价值：一个不与任何"射击爽游"共享词根的名字，货架上一眼就能分辨。

**风险与对冲：** 太陌生——商店页需要一句解释，且这句话本身要有味道（"kelo：泰加林里枯死却不倒的松树，老兵用它认路"）。中文「寒枝」与英文不同源，属"意象同源"配对，需要在双语物料里各写一句解释；若团队不想承担这个解释成本，可把中英文都退回「枯立木」，但会失去文学性。

**工程值：** 4 字符、命名空间 `Kelo`，repo `kelo`。

---

### #5　ESKER / 石脊

**为什么适合"指挥九人小队"：**

1. **它把"路线"变成一个有形状的东西。** 沼泽里唯一干燥的路是一条冰川垄脊——你必须找到它、沿着它走、在它分叉时做决定。这就是本作的路线规划玩法，具体到可以画出来。
2. **它是"距离"这个敌人的解药。** 设定里说最先要打败的是冷、湿、虫、距离；esker 正是缩短距离的那条线。名字与"任务区域"直接咬合。
3. **它让玩家记住一个地形词，而不是一个形容词。** 好游戏名常常教会玩家一个具体名词（esker、kelo），玩家学会它的时候，也学会了这个世界的规则。

**风险与对冲：** 拼写与发音有轻微不一致，需要在首曝时用一次语音/字幕把它念对；"Echo's Esker" 与 Esker 软件公司会分走部分搜索——保持 `esker` 单词形式并配合副标题，可缓解。

**工程值：** 5 字符、命名空间 `Esker`，repo `esker`。

## 4. 项目工程命名建议

### 4.1 原则

1. **工程名先冻结，市场名后调整。** 理由见 §1.3。
2. **工程名只用 ASCII 拉丁字母**，长度 ≤ 12，单数、无空格、无连字符、可作 C# 标识符。
3. **命名空间用 PascalCase，不用缩写。**
4. **repo 名用 kebab-case 全小写。**
5. **中文名不进代码、不进路径、不进 exe。**

### 4.2 以 `ILVES` 为准的具体建议

| 项 | 建议值 | 说明 |
|---|---|---|
| Unity Product Name | `Ilves` | exe＝`Ilves.exe`；首字母大写、无空格，Steam 启动项不用加引号 |
| Unity Company Name | `Understory`（推荐）或 `Ilves Works` | 工作室名应与单款游戏解耦；它会进入存档路径与注册表，换公司名＝存档搬家 |
| 中文发行名 | 猞猁 | 只出现在 Steam 本地化名、商店页、宣传物料；**不要填进 Product Name** |
| Application Identifier | `com.understory.ilves` | 反向域名、全小写、无连字符；安卓/iOS 发布后永久不可改 |
| C# 根命名空间 | `Ilves` | 子命名空间：`Ilves.Core` / `Ilves.Sim` / `Ilves.Squad` / `Ilves.Terrain` / `Ilves.AI` / `Ilves.UI` / `Ilves.Data` / `Ilves.Tools` |
| asmdef | `Ilves.Core.asmdef` 等 | asmdef 名与命名空间一致，避免两套词表 |
| Scripting Define | `ILVES_DEV` / `ILVES_CHEATS` | 全大写下划线 |
| PlayerPrefs 前缀 | `ilves.` | 统一前缀，便于一键清理与迁移 |
| 存档目录 | `Ilves/Saves` | 与 Product Name 一致 |
| GitHub repo | `ilves` | 若该名在自己账号下已被占用，用 `ilves-tactics`；**不要用中文 repo 名** |
| repo 描述 | `Ilves — squad-command tactical game in the Karelian taiga. 中文名：猞猁` | README 首行双语，直接吃搜索流量 |
| 主分支 | `main` | 保护分支；不要用 `master`（新仓库默认已是 main） |
| 集成分支 | `dev` | 所有功能分支先合 dev，再按里程碑合 main |
| 分支前缀 | `feat/` `fix/` `art/` `data/` `content/` `release/` | 例：`feat/squad-order-wheel`、`content/mission-03` |
| Tag | `v0.1.0` | 语义化版本，与 `release/x.y` 对齐 |
| GitHub Topics | `unity` `tactical` `squad-command` `single-player` `taiga` `karelia` `military-fiction` | 前 5 个最影响可发现性 |

### 4.3 如果最终定名 `DEAD GROUND` 或 `NINE PINES`

| 项 | DEAD GROUND | NINE PINES |
|---|---|---|
| Product Name | `DeadGround`（连写，避免 exe 名带空格） | `NinePines` |
| 命名空间 | `DeadGround` | `NinePines` |
| repo | `dead-ground` | `nine-pines` |
| Define | `DG_DEV` 或 `DEADGROUND_DEV` | `NP_DEV` |
| 注意 | 名称含 "Dead"，商店页分级/算法联想需观察 | 两词都常见，repo 描述必须带 "tactical game" |

### 4.4 GitHub 侧要点（上传前）

- **仓库可见性**：先 private 开发，里程碑后再 public；public 前确认没有第三方付费素材、没有个人信息、没有未授权字体。
- **许可**：代码与美术分开——代码 `LICENSE`（MIT/Apache-2.0），`LICENSE-ASSETS`（All rights reserved）。只写一个 MIT 会被理解为"整个仓库包括美术都开源"。
- **.gitignore**：Unity 模板（`Library/` `Temp/` `Logs/` `obj/` `Build/` `UserSettings/`），否则仓库会被编辑器缓存撑爆。
- **.gitattributes + LFS**：`*.psd` `*.png` `*.tga` `*.fbx` `*.wav` `*.mp4` 走 LFS；`.unity` 场景是 YAML 文本，不要进 LFS（否则 diff 全废）。
- **命名一致性**：仓库名、Unity Product Name、Steam 商店页名、README 标题必须是同一个 ASCII 串；中文名只在本地化位置出现。

## 5. 反面清单

### 5.1 已被用滥的"冷"词（分析为什么烂）

**代表词**：Whiteout、Frostline、Frostbite、Arctic、Boreal、Tundra、Permafrost、Taiga、Snowblind、Cold Front、Zero Hour。

**为什么不能再用：**

1. **它们是"环境贴图"，不是"专名"。** 这些词的语义只有温度，没有独特所指；Steam 上同义词之间可以互相替换，用户记住的是"又一个雪地游戏"，而不是你。
2. **搜索被同义词淹没。** 搜 Whiteout 出来的是几十款雪地/生存作品；你的商店页在第 3 页之后，等于不存在。冷词越通用，SEO 成本越高。
3. **标题承诺与玩法错位。** 极寒词承诺的是"生存/雪地/天气"，而本作承诺的是"决策/调度/克制"。玩家带着"雪地射击"的预期进来，差评第一句会是"以为是大雪地生存游戏"。
4. **中文侧同样失效。** 雪线、冰原、极地、寒区早已是类型标签；「雪线」「极地」作为名字，等于没起名。

> 一句话：**"冷"是设定，不是名字。** 名字应该是一个具体的东西（树、垄脊、地形术语、动物），不是一个温度。

| **Lynx 相关** | 雅达利 Lynx 掌机、Squad 中的 Lynx ATV、多种机载设备 | "Lynx" 单词不可作标题主体；`Ilves` 不受影响 |
| **Dead Ground** | 同名小说至少两部（无同名游戏） | 可用，但需正式检索并以副标题区隔 |
| **Nine Actual / Nine Pines / Kelo / Esker / Ilves / Snag / Larch / Halla / Birch** | 本轮未查到同名商业游戏 | 可用，仍需正式检索 |
| **Stand-To / Emcon / Unmapped / Lie Low / Bated Breath / No Such Unit** | 无同名游戏，但有同名短语/商品 | 可用，SEO 需注意 |

### 5.3 Ghost / Wildlands 式命名（明确避开）

**公式**：`Ghost / Phantom / Specter / Shadow / Wraith / Reaper` + `Recon / Squad / Team / Unit / Company`。

**为什么烂**：

1. **强绑定 Tom Clancy 系**，观众第一反应是"仿品"，而不是"新作"。
2. **语义指向个体精英英雄主义**（幽灵、影子＝一个人潜行），与本作"你不出手、你调度九个人"的玩法相反。
3. **这些词在商店里已是背景噪声**，无法形成记忆点。

同理避开：`Operation` / `行动`、`Squad`（已有同名大作）、`Commando`、`Firefight`、`Killzone`、`Strike`、`Assault`——它们承诺"射击爽游"，与本作"决策 + 克制"直接冲突。

### 5.4 结构与技术雷区

| 雷区 | 后果 |
|---|---|
| 西里尔字母做正式英文名 | slug 化、排序、字体、URL 编码、Steam 搜索全部踩坑；西里尔只留作战徽与世界观内文本 |
| 变音符号（ä ö å ø） | 转 slug 时丢字符（Korpi ≠ körpi），文件名与云存档可能乱码 |
| 空格 | exe 名、启动项、路径都要额外处理；Product Name 最好单词连写 |
| 连字符 | 适合 repo 名（`dead-ground`），不适合 C# 命名空间（`DeadGround`） |
| 数字开头 | C# 命名空间不允许；包名/App ID 也不建议 |
| 超过 18 字符 | 手机图标下被截断，社交卡片排版困难 |
| 全大写缩写（EMCON 类） | 对非军迷等于密码，商店页点击率低 |
| 中文 Product Name | exe / 路径 / 云存档在部分系统乱码；中文只放本地化名 |
| 商标近似 | 正式上架前必须做一次正式商标检索（本轮只做网页抽查） |

### 5.5 "看起来很好、其实不能要"清单

- **猞猁准则**（4 字）：听起来像设定集/手册标题，不像游戏名；但非常适合做**系统名/成就名**（例如"猞猁准则：全程未触发警报"）。
- **山猫**：比「猞猁」软，但"山猫"在中文里也指豹猫等，且已有同名作品/品牌，不建议。
- **白夜**：卡累利阿确有白夜，但 Dostoevsky《白夜》与同名游戏已占用。
- **深林 / 寒枝 / 九松 / 死角 / 屏息**：作为单字词很干净，但需确认没有同名国内网文/短剧（中文侧侵权检索与英文侧不同，需在发布前单独查）。
- **无名 / 无痕 / 留白**：中文语义好，但"留白"太抽象、"无名"太常用、"无痕"有日用联想；只作候选，不作首选。
- **Cold / Frost / Snow 任何组合**：见 §5.1，一律不用。

## 6. 附录

### 6.1 落地前必须人工确认的 9 项

1. **正式商标检索**：中/美/欧/俄，Nice 分类 9（软件）、41（娱乐）、28（游戏周边）。
2. **Steam 同名检索**：SteamDB 搜词根 + 变体（含连写/空格/复数）。
3. **App Store / Google Play 同名**：移动端若要做，标题必须与商店名一致。
4. **域名**：至少拿 `.com` 与 `.game`；拿不到就用 `get<name>.com`，但 repo/社交账号必须同名。
5. **社交账号**：X / YouTube / B站 / 微博 / Discord 服务器名一次性注册。
6. **俄语区**：确认该词在俄语里没有不雅/政治敏感谐音（例如 `Korpi` 在俄语里无意义，但 `Halla` 需确认）。
7. **Unity 资源命名**：Product Name 定稿后再建工程；改名会连带存档路径。
8. **中文侧侵权**：中文名要单独查同名网文/短剧/游戏；英文干净不等于中文干净。
9. **徽章一致性**：设定文字写"两颗松果"，队徽图上可见**三颗**——此项属实，必须统一（建议改文字）。~~"抓痕划破外圈"~~——【Lead 复核 2026-10-25】放大逐项核对后确认：三道抓痕**划穿的确实是内圈、外圈完整**，与文字设定一致，此条误判已撤销。详见 设定集 §3.4。做标题锁定版（title lockup）前只需解决松果数量。

### 6.2 核查方法与免责

- 本轮为**网页抽查**（Steam / SteamDB / IndieDB / GitHub / 通用搜索），日期 2026-10-25；命中项已在 §5.2 列出。
- **不是**正式商标检索，也不覆盖俄语区与中文网文/短剧领域；任何最终定名都应做一次正式检索。
- GitHub 侧抽查结果：`github.com/ilves`、`github.com/kelo`、`github.com/esker`、`github.com/dead-ground` 已存在同名账号（**顶格账号名不可用**，但作为自己账号下的**仓库名**不受影响）；`github.com/nine-pines` 为空。
- Steam 侧抽查结果：TreeLine、Mire、Defilade 已有上架作品；No Trace 有独立游戏项目；Korpi 有同名工作室。

### 6.3 一句话总纲

> **用一个具体的名词命名一片林子，用这片林子命名一场必须克制的战争。**
> 不要用温度（冷/雪/霜），不要用动作（打击/突袭），不要用幽灵（个体英雄）。
> 用一棵站着的枯树、一条沼泽里的干路、一只看过你就走的动物。

## 7.2 为什么是 ILVES

1. **唯一从既有资产里长出来的名字**：徽章上已经刻着 ИЛВЕС。不需要新造品牌，只需要把部队名放大成作品名——臂章、档案、任务简报、UI 抬头可以全链路复用，改名成本为 0。
2. **名字与玩法同构**：猞猁准则（潜伏优先／一击脱离／不追不恋）本质是一套**指挥纪律**。玩家每下一次"进 / 不打 / 撤"的命令，都是在执行这个名字。标题即规则手册。
3. **工程值最优**：5 字符纯 ASCII，Ilves.exe、命名空间 Ilves.*、repo ilves、com.understory.ilves 全部自然成立，没有一处要妥协。
4. **绕开了全部已知雷区**：提案里"已核实有主"（Treeline／Mire／Defilade／No Trace／Korpi）与"已被用滥"（Whiteout／Frostline／Taiga）都不涉及它。唯一残留风险是芬兰坦佩雷冰球队的同名搜索混淆——不同品类、不同语言语境，商店页首行写明 "a squad-command tactical game" 即可对冲。
5. **它不适合谁**：如果发行目标是"让国际玩家 3 秒看懂是战术射击"，ILVES 不如 DEAD GROUND 直白。本作既然卖的是"克制与决策"而不是"射击"，这点反而成立。
